# 功能设计归档

本目录用于保存功能设计、行为调整方案和重要技术决策。每个功能使用一个独立 Markdown 文件，命名格式为：

```text
YYYY-MM-DD-功能短名.md
```

例如：

```text
2026-09-05-login-authentication.md
```

## 设计文件模板

```markdown
# 功能名称

## 背景

说明为什么需要该功能，以及当前存在的问题。

## 目标

列出本次需要实现并可验证的结果。

## 非目标

明确本次不处理的范围，避免需求扩张。

## 方案

描述页面、组件、模块及其职责边界。

## 数据或状态流

描述数据来源、状态存放位置、更新时机和持久化方式。

## 接口与路由影响

列出新增或变更的接口、Mock、路由和权限要求；不适用时写“无”。

## 异常处理

描述失败、空数据、加载中、重复操作和权限异常等状态。

## 验证方案

列出构建、自动化测试和浏览器验证路径。

## 变更记录

- YYYY-MM-DD：创建初始设计。
```

## 维护规则

- 设计归档应与功能代码在同一次任务中更新。
- 同一功能的小幅迭代更新原文件，并追加变更记录。
- 方案发生根本变化时，可以新建设计文件，并在新旧文件中互相引用。
- 设计文件记录“为什么”和边界，`CHANGELOG.md` 记录用户最终得到的变化。
